## 离线评分的输入和用法

清单沿用probe的JSON数组，增加样本身份、分组和人工检查，不在仓库提交私人录音/参考稿：

```json
[
  {
    "id": "mic-001",
    "path": "/private/new-samples/001.wav",
    "reference": "预算1500元，不是15000元。",
    "reference_provenance": "人工逐句回听校对",
    "categories": ["number", "negation"],
    "recording_group": "recording-001",
    "split": "tuning",
    "checks": [
      {"kind": "number", "expected": "1500"},
      {"kind": "negation", "expected": "不是"}
    ],
    "semantic_review": null
  }
]
```

`reference:null`表示未标注，不得从模型输出反造参考；静音参考用空字符串。`semantic_review`由人工填写逐句/全文的语义是否保留、引入错误和复核依据，自动字面检查不替代该判断。数字检查`1500`不会因为输出包含`15000`就通过，但出现了该字面量仍不证明它对应正确事实。

```bash
# 新录音获得运行许可后，沿用实际probe；--cleanup另需远端调用授权
.venv/bin/python scripts/probe_dictation.py \
  --project-root <已准备好的隔离测试root> \
  --manifest <manifest.json> --candidate dual --realtime --output <新的运行目录>

# 仅离线读取，不启动模型或HTTP请求
.venv/bin/python scripts/score_dictation.py \
  --manifest <manifest.json> --run <一个候选的运行目录> --output <新的评分目录>
```

评分保留原始参考/输出和配置，原始ASR统计字符替换/删除/插入/CER。归一化规则固定NFC/casefold、去空白和普通标点；保留数字形式、中文数词及数字附近的小数点/负号等，不把1.5与15、一千五与一万五合并。失败/缺失产物留在分母与失败计数，静音误识别单列；重复语句ID、失败片段和各项延迟/资源保留。同录音组跨调参/留出或重复/多余产物会拒绝。

逐句/全文整理分别保留输出和人工语义复核，不按CER自动判好坏。快速文件的耗时不进入实时延迟汇总。每次候选只改一个主要因素，独立输出，同源比较调参/留出及数字/否定/条件严重错误，再决定采纳/可选/拒绝。当前**工程功能完成、质量评测未完成、准确率改善未证实**。
