# 四大能力模块重构方案

本次把现有处理操作提取为可独立调用的能力，再由现有读书会、批处理、单阶段、PDF 工具和听写功能组合调用。目标不是只移动文件，也不是增加新业务。基线为 `41bca0c19218c4eaaec1d51b45525e765dc53d00`。

**实施状态：已完成代码提取、现有功能接线和离线工程验收。** 实际接口和组合示例见 [后端能力使用指南](BACKEND_MODULES.md)。下面保留实施设计，实际验证与审核结论见文末。

用户已授权完整方案与实施：主代理负责设计、接口协调和审核；代码、环境准备及执行由 `gpt-6.1-sol` 子代理承担，复杂任务使用 `max`，集成与文档使用 `xhigh`。所有者在同一工作区工作，不提交、推送、部署、重启既有服务。

## 结果必须能这样使用

- 格式转换：明确源文件、目标文件、音频参数即可转换，无需项目 YAML 或 job。
- 本地 ASR：文件／长音频与流式／短句属于同一能力域，分别保留算法和模型生命周期；明确传入模型选项、资源目录与输出位置。
- PDF：单 PDF 经逐页识别、检查点恢复、完整性检查，生成带现有页面标注的 TXT；可注入网关，无需 FastAPI 或完整项目配置。
- LLM：通用网关调用与具体文字处理任务分离；读书会／对谈校对、听写逐句／全文整理可独立调用。提示词与各任务的结果校验归任务，PDF 专用提示词归 PDF。
- 现有入口实际调用新能力。新接口不能仅在内部构造完整 `LoadedSettings` 再调用全部旧流程；旧接口可以把历史配置转换为能力参数。

## 依赖与状态边界

`Web / CLI -> 产品编排 -> media / asr / pdf / llm.tasks`。PDF 可使用 `llm.gateway`；网关不能导入 PDF、精修或 Web。精修只消费 ASR 的结果／配对层。页面标记保持轻量单一定义。

听写 owner、正文版本、人工编辑、暂停／结束、历史、共享识别排队继续由原听写服务管理。共享的是识别操作和底层资源，不合并产品状态机。保留同一 GPU 文件锁及 fd 继承，文件识别阻塞、听写非阻塞和暂停保留资源的差异。

## 三个实现所有者

1. **media_asr（max）**：`src/media/`、`src/ffmpeg_utils.py`、`src/asr/`、`src/asr_utils.py`、听写 audio/streaming_asr/final_asr/worker 的能力迁移，以及对应测试。独占验证环境准备。保留旧 worker 入口和旧类型／异常导入路径。不得改听写 service/scheduler/cleanup 或共享 Web 任务文件。
2. **llm（max）**：`src/llm/`、`src/codex_lb_client.py`、`src/refine_utils.py`、`src/refine_inputs.py`、`src/request_trace.py`、`src/dictation/cleanup.py`、必要的听写 service 连接注入、`src/web/frontend_settings.py` 及对应测试。拥有网关连接接口；先交付明确连接／代理隔离方式给 PDF/集成所有者。不得修改 `src/web/tasks.py`、`src/job_runner.py`、阶段脚本或 PDF 实现。
3. **pdf_pipeline（xhigh）**：PDF 能力及旧 reference/pdf_book/ocr 适配、`src/pipeline/`、阶段脚本、`src/job_runner.py`、`src/web/tasks.py` 的接线与网关环境上下文替换、必要 API 适配、相关测试与使用文档。等待网关接口后接入，不复制网关实现。最终由此所有者执行集成验证并修复自身接线问题；其他所有者负责其代码修复。

主代理独占本方案文档；实现所有者交付路径、接口、验证结果和实际缺口。交叉文件修改先协调，不同时写同一文件。

## 实施次序与完成条件

1. 准备当前工作区 `.venv` 和本地验证工具，运行基线测试；不安装或下载新模型，不读取凭据。媒体／ASR、网关／文字任务、PDF 的独立提取可以并行。
2. 网关先提供独立连接和传输参数。新能力和当前产品运行时不通过临时修改进程环境切换 URL、凭据或代理；旧 CLI 环境配置在适配边界解析，凭据不写入任务快照、日志或文档。旧环境上下文仍保留原语义供历史调用，不用于新产品并发执行。上下文传播若采用 contextvars，必须覆盖线程池提交与后台线程，不可仅在入口设置后假设生效。
3. PDF 和产品编排接入新网关；阶段执行核心迁入 `src`，脚本保留 CLI 行为与兼容出口。ASR 结果消费对齐新的纯结果接口。
4. 四模块均具备独立合同测试和实际生产调用方；补充简明使用指南，示例覆盖读书会、纯文件转写、听写、PDF 四条组合。
5. 全量 `.venv/bin/python -m pytest` 通过；主代理对最终 diff 和调用方进行审核，修复实质问题后再交付。

## 兼容性与不变量

- 不改变 API 路径、CLI 参数／退出码、启动入口、历史配置含义、主 JSON、目录布局、模型 revision 和默认组合。保留 `None` 继承与空字符串／False 显式关闭。
- 不改提示词正文、引用锁定、单／双 ASR 不同处理、多后端人工选择、SSE 完成条件、请求超时与全文整理共同期限。不新增原来未发送的 token 或温度参数。
- 双 ASR 的配对完整性、结果发布与失败门禁保留；不修改历史产物。
- PDF 空白页合法；页序与 `----- OCR_PAGE_BREAK: 1 -> 2 -----` 标记不变。检查点身份与参考／书籍根目录隔离不变；不把提示词等新字段加入旧身份。补页切模仍仅在既有显式入口生效。
- PDF 明确成功／部分完成／失败，只有完整产物成功发布才交付；`resumable` 不是成功判据。旧适配器维持既有异常与删除陈旧参考 TXT 的门禁。
- 听写生命周期、人工编辑保护与取消后的真实 worker／HTTP 退出顺序不改。
- 不删除旧两步校对、CLI 模型后端、文字层／Tesseract 等待确认历史入口；align/classify、导出、TXT 合并继续有效。

## 验证与证据

- 可维护性：每个能力能在无 job、无 Web、无完整配置的临时工作区直接调用；依赖检查与调用方测试证明新模块被使用，而非仅有未接线 facade。
- 兼容性：复用现有测试并补新边界测试；不为保通过削弱状态、时间戳、配对、提示词或产物断言。内部 monkeypatch 接缝可迁移到真实新所有者，但必须保留同一行为覆盖。
- 可靠性／配置隔离：不同网关连接交错执行时 URL、认证和代理不串用；验证失败、缺页、恢复、跳过和终态。
- 实际运行：使用本地合成短视频／音频经真实 ffmpeg 转换并检查媒体参数；使用可控本地 PDF 与假模型传输运行真实页面处理／检查点／合并；组合处理运行真实编排与产物写出。不可控模型边界可用本地固定响应，必须如实标注，不宣称模型质量或 GPU 推理已验证。
- 不进行新 ASR 推理、远端 OCR/LLM 调用、模型下载或用户数据改写。基于已有固定结果的离线 ASR 配对／校对验证可执行。
- 全量验证只在候选稳定时执行，变化后按风险重验；依据 `docs/REVIEW_CHECKLIST.md` 自查。环境缺失或真实验证不能完成时，记录具体影响，不宣称全量完成。
