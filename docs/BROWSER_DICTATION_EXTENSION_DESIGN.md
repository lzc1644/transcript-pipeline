# 浏览器语音输入扩展：实现设计与模型交接

状态：设计交付，尚未实现。日期：2026-10-24。

本文件供后续执行模型使用。用户已确定只向**浏览器网页输入框**输入，要求 Chrome、Firefox 两种扩展，并在现有网页引导安装。本轮授权为设计；开始实现、发布或部署仍以用户后续指令为准。

实际部署前提：服务运行在用户自己的局域网主机，当前入口为 **`https://192.168.0.252:8443`**。浏览器可能在另一台电脑上；不能把“本地服务”写成浏览器电脑的 localhost，也不能假设存在公网 API。具体传输、证书和验收契约见第 3.4 节。

## 1. 要交付的体验与核心决定

用户打开语音输入网页，安装并连接扩展。在另一个网站的输入框放好光标，按快捷键开始听写，再按一次结束。系统完成识别和校对后，将结果一次性插入原位置，不按发送键，不提交表单。

采用**现有网页作为录音端，扩展作为输入端**：

```text
目标网页的输入框
  ↕ 扩展内容脚本：保存输入位置、校验、回填
扩展协调器：快捷键、操作绑定、消息路由、提交状态
  ↕ 已授权服务网页中的桥接内容脚本
录音网页 /dictation/extension：麦克风、预览、校对结果
  ↕ 原来的同源 HTTP / WebSocket
现有 /api/dictation → CPU 预览 → Qwen 最终识别 → 逐句校对
```

关键决定：

- 不做桌面程序、本地辅助进程、系统输入法或浏览器外自动粘贴。
- Chrome、Firefox 共用 TypeScript 核心，分别构建 Manifest V3 扩展；不维护两套业务规则。
- 录音网页必须保持打开，可以切到后台；关闭网页后不继续录音。后台扩展进程不持有麦克风。
- 扩展不直接调用后端 API，不读取 Cookie，不携带校对供应商密钥；原有同源鉴权、HTTPS/WSS 和音频协议不变。
- 不使用剪贴板实现默认回填；正常路径直接修改输入控件并通知其页面框架。复制仅作为用户主动选择的恢复动作。
- 默认使用已有**逐句校对完成后的全文快照**，不是停止后再自动调用一次全文模型。全文校对继续在网页中显式预览、确认；不暗中增加调用成本。
- 临时识别只在录音页预览，绝不进入目标框。已经提交到其他网页的文字，不随迟到结果再次修改。
- 首版只允许一个未结束的扩展操作；有待处理结果时，用户须先提交或放弃回填，再开始新操作。原服务的单活动会话限制保持。

### 完成与发布分开

工程完成：两种扩展可在独立测试配置中安装运行，录音、校对、自动回填与恢复路径有真实证据，原网页回归通过。

公开可用：两种扩展完成商店审核/签名，配置真实商店地址，网页已部署。开发包加载成功不等于商店安装完成；本设计不授权提交商店或部署。

已确认的当前事实：

- `App.vue` 通过 `provideDictation()` 创建应用级唯一控制器，页面和面板共用它。
- `useDictation.ts` 将历史选中会话 `session` 与实际录音会话 `recordingSession` 分开；选择历史不会转移录音所有权。
- `PcmCapture` 已有 live/local/probe 所有权、尾包 flush、设备选择、迟到权限保护。必须复用，不能在扩展重写第二套 PCM 采集。
- `start()` 目前返回空值，忙碌时直接返回，失败写入响应式 error；不能把一次调用 resolve 当作开始成功。
- `stop(id)` 要求明确会话 ID；历史停止与当前录音有不同处理。扩展不得用当前历史选择或 `stop(null)` 猜目标。
- 后端 `completed` 仍可能含 `asr_failed`、`cleanup_failed` 或 `needs_review`。`draft_text` 可包含整理失败时的原稿，不代表已完整校对。
- `Storage.render_draft` 是唯一正文投影；人工编辑、全文建议及版本保护已实现。禁止自行拼出第二种正文。
- 逐句和全文校对默认总期限均为 3600 秒；不是实时完成承诺。原模型、期限、4 小时/512 MiB 文件能力不因本功能改变。
- 后端只允许一个活动实时/上传任务，GPU 与旧批处理互斥；忙碌时必须明确提示，不抢占、不启动另一实例绕过锁。
- 历史事项 `codestable/issues/2046-o-two-pass-dictation.md` 原范围排除了扩展/系统输入。它是复用依据，不把本次新增能力追记成旧事项已完成。

## 3. 安装、连接、日常使用

### 3.1 安装引导

在 `/dictation` 页面新增独立引导组件，不用阻断弹窗，不挤压正文与现有录音按钮。

目标示意：

```text
在其他网页中语音输入
安装扩展，将校对后的文字填入网页输入框。
[安装 Chrome 扩展] [Firefox 版本] [连接帮助]

已连接时：扩展已连接 · Chrome · 版本 x.y.z
[打开录音页] [检查连接] [设置快捷键]
```

- 浏览器识别只决定突出哪个按钮，不替代能力检测，始终保留另一个浏览器入口。
- Chrome 跳转 Chrome Web Store；Firefox 跳转 AMO。最终安装/权限确认由浏览器完成，不宣称静默安装。
- 商店 URL 用两个显式发布配置值提供，例如 `VITE_DICTATION_CHROME_STORE_URL`、`VITE_DICTATION_FIREFOX_STORE_URL`。未发布时显示“扩展尚未发布”，正式安装按钮不提供假链接；开发加载说明单列。
- 配置 URL 必须是 HTTPS 且对应官方商店主机；网页只链接，不自动下载并执行代码。
- 状态为“未连接 / 正在检查 / 已连接 / 版本不兼容 / 网站权限未授予”。无回应只能显示未连接，不能断言未安装。
- 首次未授权服务网站时，网页没有可靠的扩展探测通路。引导用户从浏览器工具栏打开扩展并连接；不得通过扫描其他扩展、安装标识或浏览器指纹检测。

### 3.2 首次连接

1. 用户安装扩展，打开扩展设置页；可以填写服务地址，也可以在当前语音输入网页打开扩展工具栏面板，核对并选择“连接此服务”。当前部署填写 `https://192.168.0.252:8443`；从已有网页连接时，以浏览器提供的该 tab URL 提取 origin，用户确认后保存，不相信任意网页消息自报的服务器地址。地址属于用户连接配置，不在通用扩展逻辑中写死、不扫描局域网。
2. 扩展自己的界面显示完整服务 origin，包括端口。用户点击连接时，申请该服务主机的可选权限；网页发来的消息不能自行批准权限或更换服务器。
3. 只接受可信 HTTPS；允许开发用 HTTP `localhost`、`127.0.0.1`、`[::1]`，不接受普通内网 IP 的 HTTP。拒绝凭据嵌入 URL、非 http(s) 协议、片段里的控制参数。当前后端位于根路径，不扩展子路径部署能力。
4. 用户自行完成内网 CA 信任，不关闭 TLS 验证。扩展打开或经用户确认绑定专用录音页 `/dictation/extension`。
5. 在录音页点击“启用扩展控制”，确认音频保存与远端校对说明，完成麦克风授权/短试音。试音释放麦克风，不创建 ASR 会话、不调用校对。
6. 显示就绪和实际注册的快捷键。以后由扩展操作启动录音，不要求目标网站拥有麦克风权限。

更换服务时只在无录音/待提交操作时进行，撤销旧桥接注册与旧连接；旧网站不能继续发结果。旧站点权限是否保留须让用户明确选择，默认移除本扩展为该连接申请的旧权限。不要删除其他配置或浏览器证书。

### 3.3 日常听写

- 默认快捷键建议 `Ctrl+Shift+Space`，macOS 为 `Command+Shift+Space`。读取实际注册结果；冲突时显示设置入口，不强占。快捷键只在浏览器使用，不注册系统级全局按键。
- “插入待处理结果”使用第二个 command，建议快捷键 `Alt+Shift+V`（macOS 显示 Option）。扩展面板始终显示实际绑定，冲突时可配置；此动作是在目标框中明确确认一次插入，不复用开始/停止键猜测意图。
- 快捷键在空闲时锁定当前输入位置并开始；在准备/录音中再次触发，结束本次操作；处理/提交期间重复触发不新建任务。
- 工具栏面板提供同等的开始、结束、取消、打开录音页、连接设置；打开面板可能改变焦点，所以自动提交必须重新校验目标页焦点。
- 页面顶层没有合格输入框时，先提示“请把光标放在可编辑输入框”，不先录音再猜目标。
- 准备中显示“正在准备，请稍候”；只有实际 `capturing` 且服务端 listening 后显示“正在听写”。
- 结束立即释放麦克风、保存尾包，等待 ASR/逐句校对；结果满足第 6 节条件时自动回填。
- 目标变化、校对异常或需复核时，面板显示原因，用户可查看结果、明确提交到新选择的位置，或复制；不悄悄降级成原稿自动输入。
- 本轮不新增扩展侧暂停、多任务队列或流式逐字回填。原网页仍保留其已有暂停/编辑/全文校对能力；发生此类人工操作后，当前扩展结果转为待确认，不能继续无提示自动回填。

### 3.4 局域网 HTTPS 的接收与返回通路（本部署必需）

**服务端接收的是原录音网页发出的同源请求，不是扩展域发出的跨域请求。** 浏览器扩展的“后台协调器”运行在用户浏览器里，和局域网 Python 后端是两个不同角色。

```text
用户电脑上的 Chrome / Firefox
  公网或内网页面的输入框 ←→ 扩展（浏览器内部消息，无网络回调端口）
                              ↕ 浏览器内部消息
  顶层录音标签页 https://192.168.0.252:8443/dictation/extension
                              ↕ 同源 HTTPS / WSS，连接由浏览器主动建立
局域网主机 192.168.0.252:8443：现有 Caddy
                              ↕ 保留 Host，转发 scheme 和 WebSocket upgrade
                        同一容器内 API :8000
```

| 对象 | 本部署的值或要求 |
|---|---|
| 已有语音输入页 | `https://192.168.0.252:8443/dictation` |
| 新录音页 | `https://192.168.0.252:8443/dictation/extension` |
| 会话 API | `https://192.168.0.252:8443/api/dictation/sessions` |
| 音频/事件 WebSocket | `wss://192.168.0.252:8443/api/dictation/sessions/{id}/stream` |
| 后端收到的浏览器 Origin（变更请求、WS） | `https://192.168.0.252:8443` |
| 反向代理需保留的 Host | `192.168.0.252:8443`，不能变成内部 `127.0.0.1:8000` |
| 扩展桥运行时允许的 origin | 精确等于 `https://192.168.0.252:8443` |
| 扩展可选主机权限匹配示例 | `https://192.168.0.252/*`；不把 `:8443` 塞进跨浏览器匹配模式，端口由运行时检查 |

请求/响应按如下顺序走：

1. 扩展把 START/STOP 等有限消息发给绑定的顶层录音页。录音页沿用原 `fetch('/api/dictation/...')`；WS 根据自己的 `location.protocol` 和 **`location.host`（含端口）**生成，不能用 `hostname` 丢掉 8443。
2. 浏览器管理该服务页面的 `dictation_owner` Cookie；同源 HTTP 和 WS 自然携带相应凭据。服务端仍按原 Cookie 所有权、Origin/Host 规则验证，不新增绕过认证的“插件专用接收接口”。不让扩展读取、复制或伪造 HttpOnly Cookie。
3. API 经现有 Caddy 的 loopback 反代收到请求，原 scheme 转发保证 HTTPS 场景的 Secure Cookie 语义。客户端不直连容器的 8000，不降级到 8080 HTTP，不使用 `ws://`。
4. 结果沿原 WSS 事件/同源 GET 返回录音页，再经桥发给扩展，由扩展发给目标页。服务器不主动回连用户电脑，不需要公网回调 URL、浏览器本地监听端口、NAT 端口映射或目标网站访问内网的权限。

不要让目标网站的脚本/iframe 请求内网 API，也不要从扩展 service worker/event page 直接 fetch 或创建后端 WS 来“简化”。扩展主机权限不等于服务器的 Cookie/Origin 授权；改成直连会重新引入扩展 origin、Cookie/SameSite、跨源与浏览器本地网络访问限制。本方案不把扩展 ID 加进 `TRANSCRIPT_DICTATION_ORIGINS`，不放宽 CORS，不伪造 Origin。即使采用顶层同源通路，仍须在实际浏览器版本和设备策略下验证网络许可，不能用关闭浏览器安全开关代替。

**证书与网络由访问设备决定：**

- 先在实际客户端的 Chrome、Firefox 分别打开现有 HTTPS 页面，确认没有证书警告，`window.isSecureContext` 为 true，麦克风 API 可用。Chrome 通过不代表 Firefox 的证书库也已信任。
- 按 [HTTPS.md](HTTPS.md) 导入服务器的公开 CA `data/https/transcript-lan-root.crt`，由用户/管理员确认信任；不分发 CA 私钥，不由扩展静默安装根证书，不以点击“继续访问”代替可靠信任。
- 当前证书需匹配 IP `192.168.0.252`，沿用现有 `HTTPS_DEFAULT_SNI`、Caddy 和 CA 卷。固定 IP/DHCP 保留可减少地址变化；地址变更时由用户重新确认 origin/权限，并核对证书覆盖，不静默迁移旧绑定或复制 Cookie。
- 使用电脑必须有到该主机 8443 的网络通路；离开局域网时默认不可用。VPN/公网暴露不在本轮范围。服务尚无面向公网的完整登录防护，不能为扩展上架开放公网端口。
- 同一浏览器配置内复用原网页凭据；Chrome、Firefox 及其他设备各有自己的 Cookie/历史所有权，不假定自动共享历史。两者同时发起听写仍受服务端单活动会话限制。

连接反馈分层：先“扩展已连接网页”，再显示由**录音网页**同源检测得到的“服务可用/不可达”，录音时另显示“麦克风/识别连接已就绪”。健康接口成功不等于 WS、麦克风、GPU 和校对供应商均可用；不为一次检查连接自动创建 ASR 会话。TLS 导致页面未加载时，扩展只能提示“无法连接录音页，请打开服务检查网络或证书”，不要伪造精确错误原因。401/403/WS 1008 时检查来源、凭据和占用；连接超时检查客户端网络、8443 与主机状态，不修改模型来处理网络故障。

## 4. 模块分工与代码落点

### 4.1 扩展工程

新增 `extensions/dictation/`，独立 package/lockfile，TypeScript + Vite 构建，使用成熟的 `webextension-polyfill` 统一 Promise API。不建立第二套 Vue 工作台；设置、工具栏面板用轻量 HTML/CSS/TS，沿用当前项目颜色/字号风格。

建议布局（文件可按实际实现合并，不把每个动作拆成一层）：

```text
extensions/dictation/
  package.json / package-lock.json / tsconfig.json / vite.config.ts
  manifests/                 Chrome、Firefox 差异配置
  src/background.ts          操作协调、权限、存储、事件监听
  src/protocol.ts             消息类型与运行时校验
  src/content/target.ts       输入目标、提交/撤销、幂等收据
  src/content/recorder.ts     受信服务网页的有限消息桥
  src/popup.* / options.*     扩展自有界面
  tests/                     状态、协议、真实扩展测试与夹具
  dist/chrome/、dist/firefox/ 构建输出，加入忽略规则
```

Chrome 使用 MV3 service worker；Firefox 使用 MV3 非持久 background scripts/event page，生成各自 manifest。两端都不能假设后台永久存活，也不使用 DOM、麦克风或长 HTTP 请求占住后台。

最低版本由 S1 实测与必要 API 的兼容表确定，写进 manifest、README 与验收记录；不得用“最新都支持”代替版本证据。若某端缺少必要 API，明确拒绝/缩小受支持版本，不静默改成另一种存储或权限模型。

### 4.2 网页增量

- 新增 `frontend/src/views/DictationExtensionView.vue`，注册 `/dictation/extension`。复用应用级 `useDictation`，提供采音状态、当前结果、错误、停止与禁用扩展控制。
- 新增 `frontend/src/composables/dictationExtensionBridge.ts`，只在专用页且用户已启用时接收控制。它把扩展操作绑定到具体会话，不持有第二套音频/服务器会话状态机。
- 新增 `frontend/src/components/DictationExtensionGuide.vue`，嵌入现有语音输入页，处理商店链接与有限的连接探测。普通页面仅处理握手，不接受开始录音命令。
- `App.vue` 仅为新路径采用已有紧凑布局方式，继续只提供一个控制器。新页面不依赖改写 Dock；若需协调布局，先核对正在修改的 Dock，而不是覆盖它。
- `useDictation.ts` 的 `start` 增加可判定返回值：`started(sessionId)` 或 `rejected(reason)`，保留现有调用者忽略返回值时的行为、错误提示和清理。返回 started 仅表示已绑定新会话，真正录音就绪另由状态确认。
- 给扩展调用增加可选 `AbortSignal`，绑定本次 start 的内部代次；准备阶段尚无 sessionId 时，取消只终止该代次的准备，晚到麦克风/会话立即按原规则清理。不能取消另一次网页启动；旧调用者不传 signal，行为保持。开始成功后的停止/取消使用已返回的明确 sessionId。当前工作区的 start 已有模型/推理配置参数，新增选项必须追加或采用兼容方式，不占用旧参数位置、不把旧调用改成固定模型。
- 增加按指定会话读取最终快照的窄入口，或使用桥接私有同源 GET；不得通过 `select(id)` 改用户正在看的历史来取结果。`stop/cancel` 始终使用本操作捕获的 sessionId。
- 桥接绑定完成后监听页面已有状态；`start` 返回前被取消、迟到权限或迟到创建响应必须沿用原代次保护，不得关联到前一个 sessionId。
- 常用术语复用现有校验和本浏览器术语库；在录音页明确选择，用于新会话并冻结。不默认把库中所有词全部启用，也不改变旧页面的术语行为。

后端默认无需修改。若穿刺发现必须增加字段，先说明证据与兼容影响；不放宽 `validate_origin`、不引入 wildcard CORS、不绕过所有权、不重构识别 Runtime。

### 4.3 状态的唯一所有者

| 状态 | 所有者 | 其他参与者的职责 |
|---|---|---|
| 麦克风、PCM、WS、当前录音会话 | 网页原 DictationController | 扩展发送意图并等待状态，不自行重连音频 |
| 识别/校对正文、版本、历史与产物 | 后端 Service/Storage | 网页读取原投影，不制造另一种正文 |
| 一个扩展操作及绑定、是否允许提交 | 扩展后台协调器 | UI 和内容脚本不能自行创建新操作 |
| DOM 元素、选区、修改检测、提交收据 | 目标页内容脚本 | 后台只存不透明 targetId，不保存整页/输入框内容 |

## 5. 消息、绑定与后台恢复

### 5.1 标识与消息封套

所有跨上下文消息有 `protocolVersion: 1`、固定 `type`、`requestId`；操作消息另带随机 `operationId`。回复必须匹配请求和当前绑定，不允许只按“最新会话”接收。

操作记录最小字段：

```text
operationId, generation, phase
recorder: { tabId, documentInstanceId, exactOrigin }
sessionId（创建成功后才有）
target: { tabId, frameId, documentInstanceId, targetId }
result: { sessionRevision, text, disposition, reasons }（有结果时）
commit: { commitId, status }（有提交尝试时）
```

`documentInstanceId` 由每个注入文档实例随机生成；不能只依赖 tabId、URL 或浏览器独有 documentId。页面刷新、同 URL 重载、跨站导航、BFCache 恢复后要重新握手，旧操作不得自动绑定新文档。

目标脚本只在用户触发扩展后注入。元素引用、原文字、选区、变化计数保留在该脚本内存，不传给录音网站、后端或扩展后台。

### 5.2 有限消息集

| 通路 | 消息 | 契约 |
|---|---|---|
| 扩展 UI → 后台 | CONNECT、TOGGLE、CANCEL、COMMIT_PENDING、DISCARD | UI sender 必须是本扩展；CONNECT 要经过扩展 UI 权限确认 |
| 后台 ↔ 目标脚本 | CAPTURE_TARGET、PREPARE_COMMIT、COMMIT、GET_RECEIPT、UNDO | 带 operation/target/document/commit 标识，只操作已记录元素 |
| 后台 ↔ 录音桥 | HELLO、START、STOP、CANCEL、GET_OPERATION | 仅绑定的服务 origin、tab、文档；START 只由用户操作创建 |
| 录音桥 → 后台 | STATE、RESULT、ERROR | 必须匹配 operation/session；不是任意网页提供的文本 |
| 引导网页 ↔ 桥 | HELLO/STATUS | 只公开扩展版本、协议和连接状态，不公开正文、目标或凭据 |

网页与隔离内容脚本用 `window.postMessage` 或 MessageChannel 建立窄桥；首次消息检查 `event.source === window`、准确 `event.origin`、消息 schema、方向与请求关联，发送不用 `'*'`。扩展后台再检查浏览器提供的 `sender.id/tab.id/frameId/url` 与绑定的文档实例，不信任 payload 自报的来源。

随机通道标识用于防串话，不作为对同一网页脚本的保密凭据：该服务 origin 是显式信任边界。专用页上的 XSS 仍可能伪造服务结果，因此只接受纯文本数据，不能获得任意 URL 请求、执行脚本、目标选择、剪贴板读取、历史读取或新建操作的权限。

目标网站**没有**网页→扩展的 postMessage 控制桥。不要让目标网站能够请求开麦或提交别的文本。扩展所有可执行脚本随包发布，不 eval 服务返回内容，不从服务器下载扩展执行逻辑。

### 5.3 生命周期与幂等

```text
idle → capturing_target → preparing → recording → draining → result_ready
                                                    ↓             ↓
                                                 failed      committing → delivered
                                                                  ↓
                                                        pending / delivery_unknown
任一未提交状态 → cancelled（取消自动回填；麦克风即时释放）
```

- 从 `result_ready` 进入 committing 前执行第 6、7 节的全部检查；否则 pending 并给出原因。
- START/STOP/CANCEL 按 operationId 去重。页面桥保留本页操作→session 关联；重复 START 返回已有状态，不再调用 start。
- 后台单一队列串行更新操作记录；外部请求发出前保存意图，await 返回后核对 generation/document/phase。外部调用不在长期锁内等待。
- transient 操作保存在 `storage.session`，只允许扩展可信上下文访问；服务地址/偏好放 `storage.local`。音频不进扩展存储，正文不进 sync/local 或普通日志。
- 同一后台实例的串行队列负责写入；新实例先加载记录，再探测**原**录音页和目标实例。状态无法核实时保留待处理，不新建录音、不自动回填。
- 不依赖长连接让 service worker 永久存活，不用假心跳绕过浏览器生命周期。后台重新唤醒后主动重连，录音页在结果 ready 时可通过桥重新投递同一 RESULT。
- 浏览器关闭/扩展重载导致 session storage 清除时，不从服务器历史推断新操作，也不自动开麦；历史稿仍能在原网页找回。
- COMMIT 前持久记录 `commitId=sent`。目标脚本在同步编辑前先登记 committing，完成后保存 receipt；同一 commitId 再收到时仅返回已有收据。回复丢失只查询 GET_RECEIPT，不盲目再次插入。
- 目标文档消失且无法取得收据时记为 `delivery_unknown`，提示先核对目标。人工再次插入必须是新的显式动作，并提示可能重复。
- CANCEL 先使结果失去自动提交资格，再停止该操作的音频/服务会话；原服务取消可能等待在途校对，UI 区分“录音已停”和“后台仍在退出”，不能承诺立即释放所有资源。
- 扩展控制权限撤销/服务桥断开时，不启动新录音、不自动提交。录音页必须始终有独立可用的停止按钮；禁用/卸载扩展未必能通知到网页，不将扩展退出视作麦克风已停。刷新/关闭录音页沿用现有卸载释放路径。

## 6. 什么结果可以自动输入

自动提交必须同时满足：

1. 操作没有取消或发生恢复不确定性，sessionId 与录音页绑定一致。
2. 原会话状态是 `completed`，麦克风已释放，不处于暂停、draining 或人工整理处理中。
3. 已开启逐句校对；所有实际产生的非空语句均已完成校对，无识别失败、整理失败或未完成语句。
4. 无 `needs_review`，无会影响完整性的音频丢失/中断记录；不能只检查 phase 文案。
5. 本次没有人工编辑、应用全文建议、切换成其他输入来源等改变自动结果含义的动作。
6. 取服务器最新的 `draft_text` 和对应 revision，正文非空；不拼 preview，不把 partial 当最终稿。
7. 第 7 节的目标校验通过。

不满足时明确区分：空结果 / 部分识别失败 / 校对失败但原稿可用 / 需复核 / 原稿被人工修改 / 目标已变化。用户可在录音页查看并选择“使用当前正文”，再回目标页用扩展确认插入。人工提交只放宽“自动质量”条件，不能绕过目标和幂等校验。

扩展不提供自动全文整理开关。需要全文整理时先在原网页预览并应用，之后显式选择该操作绑定会话的当前正文；不能把用户正在浏览的另一历史稿作为当前结果。

限制：单次跨扩展消息正文最多 200,000 个 UTF-16 code units，超限只提示在原网页处理/导出，不截断、不自动拆成多次输入。这是扩展回填边界，不改变原后端对长稿的能力；实现须显式校验该单位。

## 7. 输入框定位、插入与撤销

### 7.1 首版支持范围

验收必须包含：普通 `textarea`；`input[type=text|search|url|tel]`（含默认 text）；Vue/React 受控的上述控件；基础 `contenteditable` 文本编辑区。email、数字、日期等不能使用同样选区 API 的类型首版拒绝，不假设 selectionStart 总可用。只读、禁用、password，以及带 password/one-time-code 等敏感用途标记的字段也拒绝，不声称可以识别所有伪装敏感字段。

首先支持顶层文档及能在同一已授权 origin 内可靠定位的 frame；目标在跨源 iframe 时明确显示需要该 frame 来源权限，未授权就不读取/不写入。首版可将跨源 iframe 标为不支持，不能往顶层最近的输入框代填。开放 Shadow DOM 可递归定位并测试；封闭 Shadow DOM、Canvas、自定义无标准编辑接口、浏览器内部页、商店页、内置 PDF 阅读器属于明确限制。

复杂富文本（如 ProseMirror、Slate、Quill、Monaco、Google Docs）按**实测的编辑器/网站/浏览器版本**登记支持。没有验证的结构不承诺自动回填，不通过清空整个 contenteditable 来强行支持。

### 7.2 捕获与有效性

- 使用真实 focused editable；保存原生元素引用、文档实例、完整原 value 或支持范围内的编辑区状态、选区位置/方向与变化计数。非空选区表示替换该选区，不是无条件末尾追加。
- 监听目标的用户输入、选区变化、compositionstart/end、焦点迁移、DOM 节点替换及相关编辑区变化。只监听该目标所需事件，不记录用户全局键盘内容。
- 录音期间目标内容/选区被修改，即使后来撤销恢复同样文字，也取消自动提交资格，要求用户重新确认。插入前再检查实际值/DOM，覆盖页面脚本无事件修改的情况。
- IME 正在组合输入时不开始捕获或提交；不强行结束用户现有拼音输入。
- 导航/刷新、目标节点移除、编辑区被框架替换、目标 tab 关闭，都使旧 targetId 失效。不能靠 CSS selector 在新页面找到“相似位置”继续写。
- 自动写入要求原 tab 是当前聚焦浏览器窗口的活动 tab，目标页 `document.hasFocus()` 且编辑框仍是原焦点，内容/选区/代次有效。不在后台标签页悄悄输入，也不自动抢焦点。
- 工具栏面板或首次开麦会改变焦点；自动提交条件不成立时保留待确认。用户回到原框或新框按“插入待处理结果”快捷键，创建新的目标快照，明确选择使用已预览的结果，然后只对这个新快照执行一次提交。旧目标不会因切回窗口自行复活。
- 浏览器/OS 焦点切换无法形成跨进程绝对原子事务；提交前做最后的 DOM 内同步检查，明确这是应用级防误写约束，不承诺系统级锁定焦点。

### 7.3 真正让网站收到文字

扩展的 DOM 适配器对外只提供 `capture / prepare / commit / receipt / undo` 行为。每次 commit 只采用一种已验证的写入路径，不在“不知道是否已成功”后串行尝试多个 fallback。

- input/textarea：按保存选区计算完整预期值，使用原生控件能力完成替换，派发目标框架需要的 input 通知，保留光标；Vue/React 的模型值和实际提交值必须一并验证。仅赋 DOM value 而没有应用状态更新不合格。
- 基础 contenteditable：先穿刺浏览器编辑命令的 `insertText` 与选区/撤销行为。`execCommand` 已弃用，只能作为经过两端实际验证的有限适配路径，不当作未来通用保证；返回失败或网页取消编辑时停止。不得通过 `innerHTML` 注入模型内容。
- 插入只包含纯文本，保留中英、换行和 emoji；受 input 类型/maxlength 限制无法完整容纳时拒绝，不能静默截断或删换行。
- 对 contenteditable 若必须使用 Range 操作，要证明不破坏已有格式、框架模型与撤销；否则该编辑器转为明确未支持，提供用户复制，不谎报插入成功。
- 编辑前后的事件不能重复发；若浏览器原生编辑路径已发 input，不再补一遍引起二次业务更新。不伪造 trusted 事件，不执行目标站点 JavaScript 内部 API 来规避校验。
- 成功判定至少包括预期文本、选区、控件状态稳定；测试还须验证页面模型/提交值。运行时不自动提交真实表单来检测，也不能凭“已发送 COMMIT”显示已插入。
- 原生撤销可用时验证一次撤销恢复。input/textarea 另可提供“撤销本次插入”：只在仍是同一文档/元素、值和编辑代次等于本次提交后状态时恢复之前值与选区，并通知框架；用户已继续编辑就拒绝撤销，不能删除后续输入。基础富文本的撤销以已验证的编辑事务为准，不恢复整个 innerHTML 快照。

## 8. 权限与信息边界

必需权限：`activeTab`、`scripting`、`storage`。通过 commands manifest 配置快捷键。默认不请求 `<all_urls>` 必需权限、cookies、clipboardRead、webRequest、nativeMessaging、debugger 或屏幕捕获。

服务地址可配置，所以 manifest 可声明宽范围的 **optional_host_permissions**（HTTPS 与开发 HTTP），实际只在用户连接时申请所选服务的最小主机范围。主机匹配权限不能当作端口级鉴权；运行时始终验证准确 scheme/host/port 与服务路径，阻止相同主机其他端口被误认为同一服务。

目标网站通常由快捷键/工具栏动作获得 activeTab 临时授权，不长期注册全站内容脚本。服务网站的桥脚本仅注册所选服务的 `/dictation` 与 `/dictation/extension` 路径，且普通页只允许 HELLO；Chrome/Firefox 对动态脚本注册与权限撤回的行为分别验证。

扩展设置页以文本说明：音频发送给配置的服务并沿用其保留策略；转录文字可能发送校对供应商；目标输入框原文只在本页内存做冲突检查，不上传；用户明确插入之后，目标网站自然能读取该结果。

待提交正文只在 browser-session 存储和可信扩展 UI 内存中保留，提交/放弃后清理；不写遥测、不同步账号。目标内容脚本不接收正文以外的其他会话历史。错误日志记录状态/原因/操作 ID，不记录输入框值、完整语音稿、音频、Cookie、密钥或完整目标 URL。

Chrome/Firefox 默认均只支持普通窗口；首版不启用无痕/隐私窗口，避免与普通会话凭据、录音标签页混用。需要时以后单独设计隔离。

## 9. 界面与状态契约

录音页目标示意（沿用现有工作台 tokens，主操作不随正文增长下移）：

```text
浏览器语音输入                     扩展已连接
● 正在听写 · 00:18       [结束] [取消回填并停止]
┌ 当前预览/已完成正文 ───────────────────┐
│ 文本在此区域内部滚动                  │
└─────────────────────────────────────┘
麦克风：已选设备        [设置] [停止扩展控制]
```

扩展工具栏面板目标示意：

```text
语音输入                 已连接
正在校对… 麦克风已关闭
[打开录音页] [取消回填]

待确认时：原输入位置已变化
返回目标框，按 Alt+Shift+V 插入已确认结果。
[查看结果] [复制结果] [放弃回填]
```

- 初版不在所有目标网站注入浮动录音面板，避免遮挡网页和引入样式冲突；用扩展 badge/工具栏状态、录音页与必要的短提示传达状态。
- 待确认结果使用第二个 command 提交，面板只展示实际快捷键和结果，不从有焦点的 popup 内强行给页面写入。用户未配置成功该快捷键时，可进入浏览器快捷键设置或主动复制；正常自动路径不依赖第二个快捷键。复制须由用户点击触发，失败保留可选择的正文，不自动申请剪贴板读取权限。
- 若有短提示，放在浏览器视口内避开目标文本/选区，键盘可达、可关闭；不覆盖网页发送按钮、不改变网页正文布局、不全屏截获输入。收起后不得遗留透明命中层。
- 准备、录音、处理中、待确认、已插入、失败各有文字标签，不能只用颜色。
- 扩展页正文用纯文本渲染；长文可滚动，按钮固定在独立布局区。支持键盘操作、缩放、深浅主题和减少动画。
- 显示“录音页已关闭，请重新打开；已接收结果可在历史查看”而不是无限转圈；首次授权拒绝提供重试入口，不假装录音开始。

## 10. 实施顺序与停止条件

以下阶段由后续获得实现授权的模型执行；按序推进，第一轮先证明关键通路，不先铺完整商店页面。

### S1：两端录音网页控制穿刺

先按第 3.4 节核对实际 LAN 通路。localhost 的免证书开发环境只能用于局部检查，不能替代 `192.168.0.252:8443` 的证书、端口和代理验收。

搭建最小扩展和网页桥，使用真实 Chrome、Firefox 的普通配置：用户在前台录音页完成明确授权后，回另一 tab 用快捷键请求开始、结束；后台标签页 AudioWorklet 持续产生音频。使用公开短样例/本人设备，不动用户历史，不要求校对调用。

必须观察：首次权限拒绝、后台重新开麦、AudioContext suspended/resume、切换 tab、至少一次后台休眠/重建、停止尾包、关闭录音页、两次连续操作。不能沿用旧测试的 `--autoplay-policy=no-user-gesture-required`、自动授予麦克风等启动参数来证明真实权限路径。

通过条件：Chrome 与 Firefox 均能在正常权限设置下完成该体验；后台 coordinator 不持有音频且重建不双启动。若某端必须每次切回录音页点击才开始，记录实际限制，不把它说成快捷键后台录音已通过；先给出改用前台启动或扩展专用录音页的最小设计修订，再由用户确认体验变化。不要无声切换到桌面助手或只有 Chrome 的 offscreen 方案。

### S2：固定结果回填穿刺

暂不调用 ASR/校对，用有明确标记的固定文本完成跨站插入；验证 Chrome/Firefox 的原生 input/textarea、Vue/React 受控输入、基础 contenteditable、同源 frame、开放 Shadow DOM 以及不支持项提示。

包含中英、emoji、换行、替换选区、maxlength、密码/只读拒绝、IME composition、焦点/内容变化、tab 导航、重复消息与 COMMIT 回执丢失。检查实际应用模型值、模拟表单序列化、撤销，不只截图 DOM。

通过条件：支持项输入完整、位置准确、模型同步；异常情况下不误写、不重复；未支持编辑器明确保留结果。若某类基本控件仍失败，优先修本适配，不用“可复制”宣布自动回填完成。

### S3：接入现有听写与校对

接入已存在的录音控制器与状态，不改变模型、提示词、期限、词表语义。处理完整就绪判断、明确的 sessionId、取消和失败恢复；真实公开短音频跑通两种扩展。远端校对实测须有费用授权；无授权时用隔离测试网关验证协议并明确语义未验收。

通过条件：结果来自本操作、使用服务端正文投影；没有 `completed` 但 cleanup_failed 仍自动粘贴的问题；晚到结果不会修改已输入文本；原页直接听写仍可用。

### S4：安装引导、构建包和使用文档

完成两端构建、工具栏/设置/录音页 UI、连接检查、权限撤回、版本不兼容提示和开发安装说明。构建产物分别为 Chrome ZIP/unpacked 目录与 Firefox 待签名 ZIP；不得把 ZIP 重命名 XPI 冒充正式已签名安装包。

通过条件：干净配置中的安装→连接→授权→两次听写回填→退出/恢复可复现；普通语音输入页不依赖扩展也可继续使用。无商店 URL 时明确未发布，不提供坏按钮。

### S5：单独授权的商店发布与部署

发布者负责 Chrome Web Store 开发者账号/费用、Firefox AMO 账号/稳定扩展 ID、签名/审核、隐私说明、音频/文本数据用途声明、图标截图与审核操作步骤。Firefox 的数据收集声明按发布时的实际 manifest/AMO 要求填写，不能把“扩展不直接上传”写成“系统不传输音频/文字”。

审核人员需可复现的演示环境或说明，不能假定能访问用户内网服务器。演示服务、账号、成本单独授权，不能公开本机服务/凭据。商店通过后由发布者提供真实 URL，执行者配置网页并在获部署许可后发布，验证实际商店安装与升级。

自动更新由商店机制提供，不自造下载执行器。升级后录音期间不强行切换协议，协议不兼容时停止新操作并提示先完成现有录音再刷新。

功能测试至少覆盖：

1. 两端安装连接、未连接/不兼容、权限拒绝与撤回；商店未发布状态。
2. 正常纯文本、受控组件、基础富文本的插入位置、实际页面模型、换行/emoji、选区替换与撤销。

4. 按操作 ID 去重，旧 session/旧录音页结果拒绝，接收 COMMIT 后回复丢失不重复写。
5. 准备时取消、拒绝/迟到麦克风权限、停止尾包、网络中断、GPU 忙、逐句校对失败、needs_review、空音频、人工编辑。
6. 后台休眠恢复不重新开麦；录音页关闭不伪装已完成；扩展禁用后录音页仍可停止。
7. 服务域伪造消息、不同端口、同 tab 新文档、伪造 target/session、超长与 HTML 正文，均按边界处理。
8. 原网页实时录音/暂停、历史选择和 local/live 所有权的相关回归；不扩展到四小时测试。
9. 实际局域网客户端的 Chrome、Firefox，连接 `https://192.168.0.252:8443`：分别验证 CA 信任、same-origin POST、带凭据的 WSS 握手和结果回流；录音页在后台时，另一公网 HTTPS 目标网页仍可得到回填，且该目标页没有发起内网 API 请求。检查 8443 在 HTTP/WS/Origin/Host 全程保留，不把 localhost、关闭证书校验或仅 health=200 记作此项通过。网络证据不保存 Cookie 等敏感头。
10. 仅在测试客户端模拟网络不可达、录音页关闭及桥权限撤回，验证错误分层与原稿恢复；不关闭共享服务器、不修改生产防火墙或重启用户任务来制造故障。新录音页需部署后才能在实际 8443 验证，该部署仍单独授权；部署前只做已存在页面/接口的只读核对及隔离环境验证，交付时明确 LAN 扩展全链路待验收。

真实运行使用新建隔离目录 `tmp/browser-dictation-extension/<run>/`；记录浏览器/OS/扩展版本、测试 origin、操作序列、报告、截图、失败原因。固定网关结果标记为协议夹具；虚拟麦克风标记为回放，不替代物理麦克风/本人语义质量。

浏览器是本方案的平台边界。先在可用 OS 完成两种浏览器核心验收；公开声称 Windows/macOS/Linux 全支持前，每个系统至少完成安装、权限、快捷键和短录音回填的真实冒烟，记录 OS/桌面/会话类型。无需重做系统输入矩阵，也不能从“理论跨平台”推导已验收。缺失环境由拥有该环境的执行者/用户完成，不阻塞已经就绪的独立代码工作，但影响相应平台支持声明。

最后按 `docs/REVIEW_CHECKLIST.md` 自评，分别报告工程实现、真实链路、模型语义、商店发布和部署状态。无新付费授权时，实际供应商校对端到端是待验收依赖，不假报全链路完成。

## 12. 给执行模型的接手指令

用户随后授权实现时，可直接使用：

> 请按 `docs/BROWSER_DICTATION_EXTENSION_DESIGN.md` 实现 Chrome 与 Firefox 的浏览器语音输入扩展。先读取 AGENTS.md、相关现有语音输入文档与当前 diff，保护所有已有改动。实际服务是局域网 `https://192.168.0.252:8443`，先读第 3.4 节和 `docs/HTTPS.md`：扩展经录音网页同源收发，不能直接从扩展域请求 API，不能把浏览器电脑的 localhost 当作服务器。按 S1→S4 推进，先证明两端后台网页录音和固定文本回填，再接现有识别校对链路。不要把复制按钮、单浏览器通过、localhost 或 mock 校对当作完整验收。保持原网页、当前模型配置能力、Cookie/Origin 防护和中间产物契约；不新增桌面程序或重写音频引擎。按项目 .venv 测试，给出真实运行证据与实际未完成项。没有另外授权，不提交商店、不部署、不 commit/push、不调用付费服务、不重跑用户历史音频。穿刺若证明核心体验不可行，带证据提出最小方案修订，不静默缩小目标。
