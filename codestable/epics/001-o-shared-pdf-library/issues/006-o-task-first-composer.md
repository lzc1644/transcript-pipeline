# 先组合本次材料，而不是先找旧材料

用户重建后指出：单任务默认只选已发布材料，打开书库又进入完整管理/修订界面，桌面选页动作在长预览底部。根因是把复用放在了临时组装之前。用户已批准分析并修改；本事项延续 Epic，主代理负责设计和验收，worker 只执行明确实现。

## 目标交互（本次目标图）

```text
新建单任务：参考材料 [上传文件 | 从书库选择]
  点击“从书库选择”立即打开专用组装窗口（不跳转/丢失任务输入）
  已选时：材料名 · N本书/M页 [调整选页] [查看PDF]
          次要入口：[复用已有材料]

┌─ 选书与组合参考材料 ───────────────────────────────────[返回任务]─┐
│ 搜索书名/作者/版本/标签 │ 当前书名 · PDF页导航      │ 本次材料      │
│ 分页书籍列表           │ PDF第 [起] 至 [止] [加入]│ 名称（有默认）│
│                        │                         │ 1. A 25—38    │

手机：同一窗口 [选书 | 预览选页 | 本次材料(M)]；顶部页导航/选页不随预览滚走；
      底部状态/主动作始终可达，正文在中间区域滚动，不靠悬浮层遮挡。
```

稳定约束：专用组装没有书目编辑、页文字编辑或整本识别；范围起止包括两端、1起始物理页；动作紧邻预览顶部；本次有序页段一直可找到，手机一击切换。默认新建组合，旧材料复用是次级动作。书库管理内也提供显著的专用组装入口，并把管理详情的桌面选页区移到预览上方。

## 实现决定

- 复用现有 Library API、持久化草稿和固定版本，不改后端契约/数据库/模型链路。
- 独立 LibraryMaterialComposer 承担选书、原页预览、局部有序页段、草稿保存、只补缺页、发布。对外 show 与 selected(revision)；task 模式主按钮“用于本次任务”，standalone 模式“生成材料”。
- Picker 拥有窗口、已选版本摘要与次要的已存材料/版本选择器；SingleJob 切换到书库来源即打开窗口。窗口关闭保留局部选页，回到任务时视频等输入不变。已选旧版本不能被打开窗口隐式修改；更换选页生成新固定版本。
- 保存用现有 CAS；冲突保留本地输入并显示最新页段供比较、显式采用新基准。缺页统计由已保存草稿提供；本地编辑后先保存再识别/发布，不拿旧统计当新材料状态。全部准备时生成与提交不发 OCR。
- 缺页 OCR 使用服务器当前设置，启动前确认页数、模型、并发/Fast；只提交去重缺页；窗口内看进度、失败与显式继续，不自动重试/收费。
- 统一 /pdf 父入口（书库、整本OCR 子页）；旧路由重定向保留查询参数。仅合并用户信息架构，不迁移旧任务、不合并两种调度。

## 质量承诺与验证

- 交互能力：无需离开单任务即可两书多段组合；桌面/390px手机打开即找到选页，预览滚动不隐藏动作；返回任务不丢输入。浏览器真实交互与截图/边界验证。
- 正确性/可靠性：本地页段顺序、重复、缺页状态准确，缺页不能用于任务；异步切书/跳页不展示错页；冲突保留选择；已有版本不漂移。API夹具与浏览器检查。
- 兼容性：旧URL、上传、旧OCR、批量/CLI/对谈与任务快照协议不变。完整 `.venv/bin/python -m pytest`、前端构建、旧界面关键浏览器回归。

没有生产部署/重启，没有真实模型调用或ASR重跑。完成后更新使用说明和执行证据，不自动关闭或提交。
