# 前端工作台式优化

## 已确认目标与边界

用户选择“按推荐方案做工作台式优化”：优化现有六个页面的导航、布局、视觉与交互状态，保留现有功能和后端协议。保留 Vue 3、Naive UI、现有路由和深浅主题；不改后端 API、模型行为、配置持久化协议或中间产物，不新增流水线能力，不部署、不自动提交或关闭事项。

现状：App 顶部六项横向导航，页面重复 hero 和表单卡片，主色在 CSS 和组件库不一致。用户从页面选择文件与配置，经 api/client 调用既有 API，轮询状态并查看/下载产物。此次只优化这条操作链路的呈现，不重写任务执行。

无现行 Project Spec / Epic；复用已检索的历史约束：不恢复装饰背景光球；保留本机文件与服务器路径区别、单阶段全局目录警告、OCR 缺页重试与删除确认、任务配置与全局设置区别。

## 目标 UI 与实现方向

视觉：中性不透明底色、清晰分隔、统一靛蓝强调色；减少玻璃效果、大阴影和嵌套卡片，使用本地字体回退，不引入外部图片/字体依赖。
内容：导航分组；主要区域优先显示输入和常用配置；状态与结果邻近操作；高级参数按需展开。各页按任务特点使用双栏或列表，不能机械把所有内容塞进相同双栏。
交互：导航/面板短过渡、参数展开、按钮状态反馈；支持减少动画。切换主题不影响表单；响应式只改变呈现，不丢失功能。

目标示意（尺寸、文案可按实际页面适配）：

```text
┌───────────┬─────────────────────────────────┐
│ 读书会整理 │ 当前页面                 主题切换 │
│           ├────────────────────┬────────────┤
│ 新建任务   │ 输入文件            │ 当前任务    │
│ 批量任务   │ 常用配置            │ 运行进度    │
│ 任务列表   │ 高级参数 ▸          │ 结果与下载  │
│           │          [开始整理] │            │
│ 工具       ├────────────────────┴────────────┤
│ 单阶段     │ 历史记录 / 详细信息               │
│ PDF OCR   │                                 │
│ 运行设置   │                                 │
└───────────┴─────────────────────────────────┘
```

窄屏：导航可收起，内容单列；抽屉可用关闭按钮/Escape 退出并恢复焦点。菜单、选择浮层和焦点不能被容器裁切或遮挡相邻正文；悬停不得导致正文布局跳动。危险操作保留确认，运行时防止重复提交；错误不能被隐藏成空列表。

实现落点：App/NavBar 负责应用壳和导航；main.css 统一视觉 token 与通用布局；六个 view 组织表单、状态、历史；共用文件/任务组件仅做此次呈现所需适配。保留既有请求、参数默认值和生命周期，不为视觉重建业务层。

## 验收承诺

- 交互能力：六个入口在桌面和 390px 窄屏均可到达；主内容无横向溢出；深浅主题下正文、输入、状态清晰；键盘焦点可见；加载、空、错误与运行状态有明确反馈。证据：真实浏览器截图/DOM、导航、展开、主题、弹层检查。
- 兼容性：现有 API 请求字段、上传模式、危险操作确认与产物结构不变。证据：差异自查、全量 `.venv/bin/python -m pytest`、前端类型检查/构建及关键操作检查。
- 可维护性：使用现有组件库与统一样式，不引入新 UI 框架或远程资源。新增交互有可重复的浏览器检查。

真实验证不调用收费模型或重跑 ASR；可控状态使用浏览器 API fixture，需明确区别于真实后端读取与真实本地文件样例。
